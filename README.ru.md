# ocyd

**Температура CPU или GPU на экране кулера Ocypus — в Linux.**

Крошечный демон: читает датчики из sysfs / NVML и отправляет значение на экран кулера по USB HID.

## О проекте

У кулеров Ocypus есть небольшой экран, на котором можно показывать температуру процессора или видеокарты. Официальное приложение есть только для Windows, поэтому в Linux экран просто остаётся тёмным. **ocyd** закрывает этот пробел: протокол был восстановлен по USB-трафику официального приложения, а демон говорит на нём нативно.

- Температура **CPU или GPU** — на ваш выбор
- **°C или °F**
- **Лёгкий** — демон потребляет всего около 10 МБ оперативной памяти
- **Широкая поддержка датчиков** — AMD, Intel и NVIDIA (в том числе проприетарный драйвер через NVML)
- **Настраиваемые USB ID** — ничего не зашито под одну модель
- **Пользовательский systemd-сервис** — стартует вместе с вашей сессией, без демона от root
- **`ocydctl`** — изменение настроек из командной строки
- **Скрипты установки и удаления**, которые берут на себя рутину

> [!NOTE]
> ocyd находится на **ранней альфа-стадии**. На железе автора всё работает хорошо, но юнит-тестов пока нет, а код ещё не отполирован. И то и другое запланировано — см. [План развития](#план-развития).

## Поддерживаемые устройства

| Модель                      | USB ID      | Статус                                  |
| --------------------------- | ----------- | --------------------------------------- |
| Ocypus Delta A62 EX Digital | `1a2c:434d` | ✅ Протестирована                       |
| Другие дисплеи Ocypus       | Неизвестно  | ❓ Пожалуйста, протестируйте и сообщите |

Собственных USB ID у кулера нет: он представляется как обычная **«USB Gaming Keyboard»** (`China Resource Semico Co., Ltd`). У других моделей и ревизий **ID могут отличаться** — см. [Другой кулер](#другой-кулер).

## Требования

- Linux (`x86_64`)
- `sudo` — для установки бинарников и udev-правила
- `systemd` — опционально; нужен только для входящего в проект пользовательского сервиса
- Для сборки из исходников: Go `1.26+`, `gcc`, `make` (по желанию) и заголовочные файлы libudev
  - Arch Linux: `sudo pacman -S systemd-libs`
  - Debian / Ubuntu: `sudo apt install libudev-dev`
- Для температуры видеокарты NVIDIA на проприетарном драйвере: сам драйвер (NVML идёт вместе с ним)

## Установка

### Вариант 1 — архив релиза (сборка не нужна)

Скачайте `ocyd_<версия>_linux_amd64.tar.gz` со страницы [Releases](https://github.com/Dilikel/ocyd/releases) и выполните:

```bash
tar -xzf ocyd_*_linux_amd64.tar.gz
cd ocyd_*_linux_amd64
./install.sh
```

В архиве уже лежат `ocyd` и `ocydctl`; установщик копирует их из папки проекта.

### Вариант 2 — клонирование репозитория

```bash
git clone https://github.com/Dilikel/ocyd.git
cd ocyd
./install.sh
```

Если в `./bin` нет бинарников, установщик **соберёт их сам**. Чтобы принудительно пересобрать, запустите `./install.sh --rebuild`.

### Что делает установщик

Запускайте его от **обычного пользователя** (не от root). `sudo` запрашивается только для системных файлов.

| Шаг                       | Что происходит                                                                                                                                                 |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Бинарники              | Берёт бинарники из папки проекта (архив релиза) или из `./bin`; если их нет — собирает. Устанавливает `ocyd` и `ocydctl` в `/usr/bin/`.                        |
| 2. USB ID                 | Спрашивает: оставить `1a2c:434d` (Ocypus Delta A62 EX Digital) или ввести свои.                                                                                |
| 3. Правило udev           | Устанавливает `/etc/udev/rules.d/99-ocypus.rules`, чтобы ваш пользователь мог работать с HID-устройством кулера, и перезагружает udev.                         |
| 4. Конфиг                 | Создаёт `~/.config/ocyd/config.toml`, если его ещё нет (существующий конфиг никогда не перезаписывается).                                                      |
| 5. systemd _(по желанию)_ | Спрашивает, используете ли вы systemd. Если да — кладёт `ocyd.service` в `~/.config/systemd/user/` и спрашивает, **включить ли автозапуск и сразу запустить**. |

Если на вопрос про systemd ответить «нет», просто запускайте `ocyd` сами или подключите его к своей init-системе (runit, OpenRC, s6, ...) как **пользовательский** сервис.

### Правило udev

```text
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="1a2c", ATTRS{idProduct}=="434d", MODE="0666"
```

`1a2c:434d` — это VID:PID **Ocypus Delta A62 EX Digital**. У вашей модели они могут быть другими — установщик позволяет ввести свои ID и сам запишет их и в правило, и в конфиг.

> [!WARNING]
> `MODE="0666"` делает `hidraw`-узел кулера доступным для чтения и записи всем локальным пользователям. Для устройства, которое всего лишь рисует число на экране, это разумный компромисс, но о нём стоит знать.

## Удаление

```bash
./uninstall.sh
```

Удаляет всё, что установщик положил в систему: останавливает и отключает пользовательский сервис, удаляет юнит, бинарники из `/usr/bin` и udev-правило (и перезагружает udev). Отдельно спрашивает, удалять ли `~/.config/ocyd`, так что настройки по умолчанию сохраняются.

## Конфигурация

Файл конфигурации: `~/.config/ocyd/config.toml`

```toml
[display]
source = 'CPU'   # 'CPU' или 'GPU'
unit   = 'C'     # 'C' или 'F'

[device]
vendor_id  = '0x1a2c'
product_id = '0x434d'
```

- Значения **чувствительны к регистру**: `'CPU'`, `'GPU'`, `'C'`, `'F'`.
- `vendor_id` / `product_id` — строки; допускаются hex (`'0x1a2c'`, `'1a2c'`) и десятичный формат (`'6700'`).
- Демон читает конфиг **только при запуске** — после любых изменений перезапустите его.

### `ocydctl`

Редактирует конфиг за вас. Флаги, которые вы не указали, оставляют соответствующие значения без изменений:

```bash
ocydctl -source GPU            # показывать температуру GPU
ocydctl -unit F                # Фаренгейты
ocydctl -vendor 0x1a2c -product 0x434d

systemctl --user restart ocyd.service
```

| Флаг       | Значения                            | Описание             |
| ---------- | ----------------------------------- | -------------------- |
| `-source`  | `CPU`, `GPU`                        | Источник температуры |
| `-unit`    | `C`, `F`                            | Единица измерения    |
| `-vendor`  | 16-битное число, hex или десятичное | USB vendor ID        |
| `-product` | 16-битное число, hex или десятичное | USB product ID       |

## Сервис и логи

```bash
systemctl --user status  ocyd.service       # статус
systemctl --user restart ocyd.service       # перезапуск (после смены конфига)
systemctl --user stop    ocyd.service       # остановка
systemctl --user start   ocyd.service       # запуск
systemctl --user disable ocyd.service       # выключить автозапуск
systemctl --user enable --now ocyd.service  # включить автозапуск и запустить

journalctl --user -u ocyd.service -f        # логи в реальном времени
```

## Другой кулер

1. Подключите кулер и найдите его ID:

   ```bash
   lsusb
   ```

   Кулер обычно определяется как клавиатура:

   ```text
   Bus 001 Device 005: ID 1a2c:434d China Resource Semico Co., Ltd USB Gaming Keyboard
   ```

   Здесь `1a2c` — **vendor ID**, а `434d` — **product ID**.

2. Самый простой путь: снова запустите `./install.sh` и введите свои ID, когда он спросит — обновятся и udev-правило, и конфиг.

3. Либо сделайте всё вручную:

   ```bash
   # конфиг
   ocydctl -vendor 0xVVVV -product 0xPPPP

   # правило udev (VVVV и PPPP — 4 hex-цифры, здесь без 0x)
   sudo nano /etc/udev/rules.d/99-ocypus.rules
   #   SUBSYSTEM=="hidraw", ATTRS{idVendor}=="VVVV", ATTRS{idProduct}=="PPPP", MODE="0666"

   sudo udevadm control --reload-rules
   sudo udevadm trigger --subsystem-match=hidraw --action=add
   ```

4. Переподключите кулер и перезапустите демон:

   ```bash
   systemctl --user restart ocyd.service
   journalctl --user -u ocyd.service -f
   ```

Если заработало — пожалуйста, [сообщите](https://github.com/Dilikel/ocyd/issues/new/choose), и мы добавим вашу модель в таблицу выше.

## Как это работает

**Датчики.** Температура процессора читается из `/sys/class/hwmon/hwmon*/temp*_input`. ocyd находит нужный узел `hwmon` по имени драйвера и метке датчика, а при неудаче берёт `temp1_input`:

| Источник | Драйверы                                        | Метки                                          |
| -------- | ----------------------------------------------- | ---------------------------------------------- |
| CPU      | `k10temp`, `coretemp`, `zenpower`, `amd_energy` | `Tctl`, `Tdie`, `Package id 0`, `Package id 1` |
| GPU      | `amdgpu`, `nouveau`, `nvidia`, `i915`, `xe`     | `edge`, `junction`, `hotspot`, `GPU`           |

Проприетарный драйвер NVIDIA не отдаёт датчик через `hwmon`, поэтому для него ocyd использует библиотеку NVML.

**Протокол.** Раз в секунду демон отправляет один 64-байтный HID-репорт:

| Байт (с нуля) | Значение                             |
| ------------- | ------------------------------------ |
| `0`           | Report ID `0x07`                     |
| `1`, `2`      | `0xFF`, `0xFF`                       |
| `3`, `4`, `5` | Сотни, десятки и единицы температуры |
| `6`–`63`      | `0x00`                               |

## Если что-то не работает

| Симптом                         | Что проверить                                                                                                                                               |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `failed to load config`         | Нет файла `~/.config/ocyd/config.toml`. Перезапустите `./install.sh` или скопируйте туда `packaging/config/config.toml`.                                    |
| `open device failed`            | ID в конфиге не совпадают с вашим кулером, либо udev-правило не установлено / не применилось. Проверьте `lsusb`, перезагрузите udev и переподключите кулер. |
| `invalid display source`        | Пишите заглавными: `'CPU'` / `'GPU'`.                                                                                                                       |
| `thermal sensor file not found` | Драйвера вашего CPU/GPU нет в списке поддерживаемых. Откройте issue с выводом `grep . /sys/class/hwmon/hwmon*/name`.                                        |
| Сервис не стартует после входа  | `systemctl --user status ocyd.service` и `journalctl --user -u ocyd.service`.                                                                               |

## Тестирование других моделей

Пока подтверждена работа только с Delta A62 EX Digital. Если у вас другой дисплей Ocypus, пожалуйста, попробуйте и создайте [issue](https://github.com/Dilikel/ocyd/issues/new/choose) **даже если он не заработал**. Укажите:

- точную модель кулера и дистрибутив Linux;
- USB vendor/product ID из `lsusb`;
- определяется ли дисплей и обновляется ли температура;
- важный вывод `systemctl --user status ocyd.service` и `journalctl --user -u ocyd.service`.

Не прикладывайте персональные данные и логи, не связанные с устройством.

## Разработка

```bash
make build   # собрать ocyd и ocydctl в ./bin
make test    # go test ./...
make all     # fmt + vet + lint + test + build
```

Структура проекта:

```text
cmd/ocyd       точка входа демона
cmd/ocydctl    CLI для правки конфига
pkg/config     загрузка и сохранение TOML-конфига
pkg/hwmon      чтение температуры из sysfs и NVML
pkg/ocypus     HID-драйвер экрана кулера
packaging/     udev-правило, systemd-юнит, конфиг по умолчанию
```
